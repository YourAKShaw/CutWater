# Sandbox fixtures

Each `fixtures/<name>.json` describes one repository state the skill must handle: its files, whether a GitHub remote exists, what the fake GitHub returns, and the audit result expected.

| Fixture | State | Expected classification |
| :--- | :--- | :--- |
| `empty` | Empty GitHub repository, no files | not set up |
| `local-only` | Code on disk, no remote | not set up |
| `partial-community` | Community files only | partially set up |
| `partial-ci` | CI and Dependabot only | partially set up |
| `full` | Generated by running setup, then checked for a zero-change second run | fully set up |
| `has-custom-README` | A hand-written README that must produce a diff prompt | not set up, README conflict |
| `org-defaults` | Community files supplied by the owner's `.github` repository | not set up until the user accepts org defaults |

## Offline (every CI run)

`npm test` runs the bundled helper against every fixture with a fake `gh` on `PATH` (`test/integration/cli.test.ts`). It asserts the classification, that the audit makes no API mutations, that the custom README is never overwritten, and that a second setup run on `full` makes no API mutations and leaves the manifest's `updatedAt` unchanged.

## Real GitHub (nightly and before a release)

`reset.mjs` recreates the fixtures as private repositories named `cutwater-sbx-<fixture>` on a **throwaway** account or organization:

```sh
CUTWATER_SANDBOX_OWNER=my-throwaway-org node sandbox/reset.mjs --confirm
```

It deletes and recreates only `cutwater-sbx-*` repositories, needs `--confirm`, and refuses your personal account unless `CUTWATER_SANDBOX_ALLOW_USER=1` is set. Deleting repositories needs the `delete_repo` scope (`gh auth refresh -s delete_repo`). Then clone each one and run the skill's scenario evals against it; see [docs/EVALUATION.md](../docs/EVALUATION.md).
